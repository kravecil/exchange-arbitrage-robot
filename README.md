# Робот межбиржевого арбитража фьючерсов

Асинхронный робот на Python 3.12+, который в **режиме реального времени** (websocket-подписки
через `ccxt.pro`) сравнивает цены одних и тех же **фьючерсных** контрактов на разных биржах и
зарабатывает на разнице цен: покупает (лонг) там, где дешевле, и одновременно продаёт (шорт) там,
где дороже. Когда спред сужается — позиция закрывается, разница остаётся прибылью.

> ⚠️ **Дисклеймер.** Проект создан в образовательных целях. Торговля фьючерсами с плечом связана с
> высоким риском полной потери средств. Сначала долго тестируйте в режиме `paper`. Автор не несёт
> ответственности за ваши убытки.

## Возможности

- 📡 **Реальное время** — котировки (best bid/ask) приходят по websocket через `ccxt.pro`
  (`watch_order_book` / `watch_tickers`), без опроса REST в цикле.
- 🧾 **Только фьючерсы** — работа с `swap` (бессрочные, USDT-M) или `future` рынками, спот не используется.
- 🧪 **Два режима работы**:
  - `paper` — тестовый: реальные ордера **не отправляются**, робот пишет в консоль/лог, что мог бы
    открыть сделку, и ведёт виртуальный учёт PnL;
  - `live` — боевой: ордера реально отправляются на биржу (с подтверждением при запуске).
- 🔌 **Простое добавление бирж** — чтобы подключить новую биржу, достаточно добавить её в
  `config.yaml` (`binance`, `bybit`, `okx`, `gate`, `bitget`, `kucoinfutures`, …). Код менять не нужно.
- 🪙 **Все доступные торговые пары** — автоподбор всех пар, доступных минимум на двух биржах,
  с белым/чёрным списком и лимитом количества.
- 📊 **Пороги спреда** — настраиваемые порог входа (превышение «вверх»), порог выхода при сужении
  и аварийный порог разворота («вниз»), а также верхняя отсечка аномалий.
- 💰 **Учёт комиссий бирж** — берутся реальные maker/taker из `ccxt`, учитываются на обеих ногах
  и на вход, и на выход; опционально — ставка финансирования. Сигнал считается по **чистому** спреду.
- 🛡 **Риск-менеджмент** — лимит открытых позиций, лимит суммарного объёма, дневной стоп-лосс,
  cooldown по паре, максимальное время удержания, проверка баланса.
- 🔁 **Защита от «одной ноги»** — если один ордер исполнился, а второй не прошёл, исполненная нога
  немедленно откатывается обратным `reduceOnly`-ордером.
- 🐍 **Полные аннотации типов** — `mypy --strict`, конфиг на `pydantic`, линтер `ruff`.

## Как работает арбитраж

Для каждой пары бирж по каждому символу:

```
грязный спред, %  = (bid_дорогой − ask_дешёвый) / ask_дешёвый × 100
комиссии, %       = (taker_A + taker_B) × 2          # вход + выход на двух биржах
чистый спред, %   = грязный спред − комиссии − проскальзывание
```

Если `чистый спред ≥ strategy.min_spread_pct` — открываются две ноги одновременно
(лонг на дешёвой бирже, шорт на дорогой). Позиция дельта-нейтральна: движение рынка вверх или вниз
почти не влияет на результат, важна только динамика спреда.

Закрытие происходит, когда:

- спред сузился до `strategy.exit_spread_pct` (цель достигнута);
- спред развернулся ниже `strategy.exit_on_reverse_pct` (аварийный выход);
- истекло `strategy.max_position_hold_sec`.

- Python **3.12+**
- Пакетный менеджер [**uv**](https://docs.astral.sh/uv/)

## Быстрый старт

```bash
# Мониторинг спредов 60 секунд без сделок (безопасно, ключи не нужны)
uv run arb-robot scan --duration 60

# Тестовый режим: сигналы и виртуальные сделки в консоль
uv run arb-robot run --mode paper

# Список общих торговых пар, которые будет отслеживать робот
uv run arb-robot symbols

# Комиссии бирж и минимальный безубыточный спред по паре
uv run arb-robot fees --symbol "BTC/USDT:USDT"

# РЕАЛЬНАЯ торговля (потребуется подтверждение и API-ключи)
uv run arb-robot run --mode live
```

Полезные переопределения без правки конфига:

```bash
uv run arb-robot run --min-spread 0.5 --amount 50 --config config.yaml
```

Альтернативный запуск: `uv run python -m arbitrage_robot run`.
Остановка — `Ctrl+C`: робот корректно закроет websocket-соединения и напечатает итоги сессии.

## Команды CLI

| Команда | Описание |
|---|---|
| `run` | Основной режим: реальное время, поиск спредов и сделки (`paper`/`live`) |
| `scan` | Только мониторинг спредов заданное время, без сделок |
| `symbols` | Показать общие пары бирж, попадающие под фильтры |
| `fees` | Комиссии бирж и минимальный безубыточный спред по паре |

Опции `run`: `--mode paper|live`, `--config PATH`, `--min-spread %`, `--amount USDT`, `--yes`.

## Настройка (`config.yaml`)

### Управление статусными сообщениями

Периодические статусные сообщения (например, "Статус [PAPER]: пар 100 | обновлений 3035...") можно отключить:

- В `config.yaml`:
  ```yaml
  enable_status_logging: false  # по умолчанию true
  ```

- Через переменную окружения `.env`:
  ```bash
  ARB_ENABLE_STATUS_LOGGING=false
  ```

Статусные сообщения выводятся каждые `status_interval_sec` (по умолчанию 15 секунд).
Сообщения о сделках (открытие/закрытие позиций, сигналы) выводятся независимо от этой настройки.

### Режим торговли

```yaml
mode: paper   # paper — тест без затрат, live — реальные ордера
```

Режим также можно задать через `.env` (`ARB_MODE=paper`) или флагом `--mode`.
Приоритет: **CLI → переменные окружения → config.yaml → значения по умолчанию**.

### Добавление биржи

Достаточно дописать блок в список `exchanges` — код менять не нужно:

```yaml
exchanges:
  - id: binance          # идентификатор биржи в ccxt
    enabled: true
    market_type: swap    # swap — бессрочные фьючерсы, future — срочные
    sandbox: false       # testnet биржи
    leverage: 1
    margin_mode: null    # cross / isolated / null
    maker_fee: null      # null — брать комиссию из ccxt
    taker_fee: null
    ws_symbol_limit: 150 # лимит подписок по websocket

  - id: bybit
    enabled: true

  - id: okx              # для OKX нужен OKX_PASSWORD в .env
    enabled: false
```

Ключи читаются из переменных окружения по шаблону `<ID>_API_KEY`, `<ID>_SECRET`, `<ID>_PASSWORD`
(например `BYBIT_API_KEY`). Имена можно переопределить полями `api_key_env`, `secret_env`,
`password_env`. Для арбитража нужно **минимум две** включённые биржи.

Если какой-то бирже требуется особая логика, создайте наследника `ExchangeClient`
и зарегистрируйте его:

```python
from arbitrage_robot.exchanges import ExchangeClient, register_exchange

@register_exchange("okx")
class OkxClient(ExchangeClient):
    ...
```

### Торговые пары

```yaml
symbols:
  mode: auto                 # auto — все общие пары; manual — только include
  quote_currencies: ["USDT"]
  linear_only: true
  require_active: true
  max_symbols: 100           # ограничение числа отслеживаемых пар
  include:                   # приоритетные пары (в manual — единственный источник)
    - "BTC/USDT:USDT"
    - "ETH/USDT:USDT"
  exclude: []                # пары-исключения
  exclude_bases: ["USDC", "BUSD", "TUSD", "FDUSD", "DAI"]
```

Формат символа для бессрочных фьючерсов в `ccxt`: `BASE/QUOTE:SETTLE`, например `BTC/USDT:USDT`.

### Пороги спреда

```yaml
strategy:
  min_spread_pct: 0.35        # вход: чистый спред (после комиссий) выше порога — «вверх»
  max_spread_pct: 5.0         # аномалия: спред больше — игнорируем
  exit_spread_pct: 0.05       # выход при сужении спреда
  exit_on_reverse_pct: -0.5   # аварийный выход при развороте — «вниз»
  slippage_pct: 0.02          # заложенное проскальзывание
  order_amount_quote: 100.0   # объём одной ноги в USDT
  order_type: market          # market или limit
  max_quote_age_ms: 3000      # устаревшие котировки не используются
  min_top_volume_quote: 0.0   # минимальная ликвидность в стакане (0 — не проверять)
  cooldown_sec: 30            # пауза по паре после сделки
  max_position_hold_sec: 3600
```

### Комиссии

```yaml
fees:
  use_exchange_fees: true     # брать реальные maker/taker из ccxt
  default_taker_fee: 0.0005   # 0.05 % — если данных нет
  default_maker_fee: 0.0002
  fee_multiplier: 1.0         # >1 — консервативнее, <1 — учёт VIP/BNB-скидок
  include_funding: false      # учитывать ставку финансирования
  funding_pct_per_period: 0.01
```

Комиссии всегда вычитаются из спреда до сравнения с порогом входа, поэтому сделка не откроется,
если прибыль «съедается» биржей. Проверить безубыточный порог: `uv run arb-robot fees`.

### Риск-менеджмент

```yaml
risk:
  max_open_positions: 3
  max_positions_per_symbol: 1
  max_notional_quote: 1000.0     # суммарный объём открытых позиций
  max_daily_loss_quote: 100.0    # дневной стоп-лосс, после — робот не открывает новые сделки
  min_free_balance_quote: 0.0
  require_balance_check: true
```

## Практические замечания

- Начните с `scan`, затем несколько дней держите `paper` — так вы увидите реальную частоту сигналов.
- Реалистичный порог входа — комиссии (обычно 0.16–0.24 % на цикл) плюс запас. Порог `0.05 %`
  гарантированно убыточен.
- Держите на биржах примерно равные балансы: арбитраж требует одновременного входа в две ноги.
- Учитывайте ставку финансирования (`include_funding`) при удержании позиций часами.
- Скорость важна: чем ближе сервер к биржевым дата-центрам, тем меньше проскальзывание.
- Проверьте, что пары на разных биржах имеют одинаковый контрактный множитель и точность.
